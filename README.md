# SQL Case Study: Retail Sales Analysis & Data Quality Improvement

## Overview

This case study supports a **hypothetical Super Store** by identifying the
top-performing products across all categories and resolving data quality
issues through systematic imputation of missing order quantities.

> *The Super Store operates across multiple markets and regions globally,
> selling products across three main categories: Furniture, Office Supplies,
> and Technology.*

***

## Objective

The store's data team requested a SQL-driven analysis to:

- Identify the **top 5 products per category** by total sales revenue
- Surface the **total profit** generated by each of those products
- **Estimate missing quantity values** using unit price imputation,
  factoring in discount, market, and region

***

## Approach

This project was split into **two independent analytical tasks**, each
requiring a different SQL strategy.

***

### Task 1 — Top 5 Products per Category

The challenge here was ranking products **within** each category, not
globally. A global `ORDER BY sales DESC LIMIT 5` would only return the
top 5 overall — missing the breakdown by category entirely.

The solution used a **CTE + DENSE_RANK() window function**:

#### Step 1 — Aggregate & Rank

```sql
-- CTE to aggregate sales and profit per product, and rank within each category
WITH product_sale AS (
    SELECT 
        p.category,
        p.product_name,

        -- Total sales per product, rounded to 2 decimal places
        ROUND(SUM(o.sales)::NUMERIC, 2) AS product_total_sales,

        -- Total profit per product, rounded to 2 decimal places
        ROUND(SUM(o.profit)::NUMERIC, 2) AS product_total_profit,

        -- Rank products within each category by total sales (highest = rank 1)
        -- DENSE_RANK avoids gaps in ranking when there are ties
        DENSE_RANK() OVER (
            PARTITION BY p.category
            ORDER BY SUM(o.sales) DESC
        ) AS product_rank

    FROM orders AS o
    -- Join orders with products to access category and product name
    JOIN products AS p ON p.product_id = o.product_id

    -- Group by category and product to aggregate at product level
    GROUP BY 
        p.category, 
        p.product_name
)
```

#### Step 2 — Filter Top 5

```sql
-- Filter to return only the top 5 products per category
SELECT *
FROM product_sale
WHERE product_rank <= 5;
```

### Task 2 — Imputing Missing Quantity Values

Some rows in the `orders` table had `NULL` in the `quantity` column. The
goal was to estimate these missing values using the relationship:

> `quantity ≈ sales / unit_price`

The key insight was that **unit price varies** depending on discount,
market, and region — so the average had to be computed at that granularity,
not just by product alone.

The solution used **two chained CTEs**:

#### Step 1 — Calculate Unit Price per Row

```sql
-- CTE to calculate unit price for orders where quantity is available
WITH unit_price_calc AS (
    SELECT 
        product_id,
        discount,
        market,
        region,
        -- Unit price = sales divided by quantity (NULLIF avoids division by zero)
        ROUND((sales / NULLIF(quantity, 0))::NUMERIC, 2) AS unit_price
    FROM orders
    -- Only use rows with valid quantity to build the reference price
    WHERE quantity IS NOT NULL
),
```

#### Step 2 — Average Unit Price per Pricing Group

```sql
-- CTE to compute average unit price per product, considering all pricing factors
avg_unit_prices AS (
    SELECT
        product_id,
        discount,
        market,
        region,
        -- Average price grouped by all relevant pricing factors
        AVG(unit_price) AS avg_price
    FROM unit_price_calc
    GROUP BY product_id, discount, market, region
)
```

#### Step 3 — Estimate Missing Quantities

```sql
-- Estimate missing quantity values using the calculated average unit price
SELECT
    o.product_id,
    o.discount,
    o.market,
    o.region,
    o.sales,
    o.quantity,
    -- Estimated quantity = sales / avg unit price, rounded to nearest whole number
    ROUND((o.sales / NULLIF(a.avg_price, 0))::NUMERIC, 0) AS calculated_quantity
FROM orders o
-- Match each missing-quantity row to its corresponding average unit price
LEFT JOIN avg_unit_prices a
    ON o.product_id = a.product_id
    AND o.discount  = a.discount
    AND o.market    = a.market
    AND o.region    = a.region
-- Only return rows where quantity is missing
WHERE o.quantity IS NULL;
```

## What I Learned

- **`DENSE_RANK()` vs `RANK()`** — `DENSE_RANK()` never skips rank numbers
  on ties, making it the safer choice for top-N filtering per group
- **Chained CTEs** — each CTE builds on the previous one; first transform,
  then aggregate
- **`NULLIF(x, 0)`** — prevents division-by-zero errors when dividing by
  potentially zero columns
- **Unit price varies by context** — the same product can have different
  prices across markets, regions and discounts; always group by all
  relevant pricing factors when imputing
- **`::NUMERIC` cast in PostgreSQL** — required when using `ROUND()` on
  `DOUBLE PRECISION` columns
